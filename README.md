# ЭРА | VK Music Radar

Русскоязычная аналитическая панель на Next.js 16, React 19, TypeScript, Tailwind CSS 4 и PostgreSQL 17. Чёрный фон, бордовые акценты, адаптивная таблица, поиск, ТОП-100/500/1000, периоды 24 часа / 7 / 30 дней, новые хиты, графики, источники, CSV и защищённая админ-панель.

**Данные не вымышляются.** Рейтинг описывает аудиовложения наблюдаемой выборки настроенных публичных стен, а не весь ВКонтакте. Без PostgreSQL показывается состояние недоступности; с пустой БД — пустой рейтинг. Подробнее: [проверка методов и ограничения VK](docs/VK.md).

## Локальный запуск

Требуются Node.js 22.19+ (проверено на 24), npm и PostgreSQL 17 (либо Docker Compose).

```sh
npm ci
cp .env.example .env
# Укажите DATABASE_URL, ADMIN_PASSWORD (>=12 символов), SESSION_SECRET и CRON_SECRET (>=32).
# Создайте независимые случайные секреты: openssl rand -hex 32
# PostgreSQL через Docker, пароль должен совпасть с DATABASE_URL:
POSTGRES_PASSWORD=your-local-password docker compose up -d db
npm run db:migrate
npm run dev
```

Откройте локальный порт 3000 в вашей среде разработки. `/admin` — вход администратора. Секреты не включайте в Git и никогда не используйте префикс NEXT_PUBLIC_. В production обязательны HTTPS, надёжные секреты и резервные копии PostgreSQL. Сессия подписана HMAC, живёт 8 часов, cookie HttpOnly / SameSite=Strict / Secure в production. Мутации проверяют Origin. Ограничение входа: 10 попыток за 15 минут, глобальное и сохраняемое в PostgreSQL; это защищает пароль, но может временно ограничить вход для всех администраторов.

## Подключение VK

В `.env` задайте `VK_ACCESS_TOKEN`, `VK_API_VERSION` (по умолчанию 5.199), `VK_WALL_IDS` — числовые ID через запятую; сообщества имеют отрицательные ID. Сначала `npm run vk:probe` или кнопка «Проверить подключение VK» в админке, затем `npm run collect`. Проверка пытается определить владельца пользовательского токена через `users.get` и отдельно проверяет `wall.get` / `newsfeed.search`; наличие токена само по себе не означает успешное подключение. Актуальные права и возможность читать audio необходимо подтвердить вашим приложением. Значения токенов не возвращаются API и не сохраняются в журнал.

## Ежедневный сбор

Предпочтителен отдельный worker/cron на том же сервере с доступом к `.env`:

```sh
npm run collect
```

Пример ежедневного расписания (00:10 UTC, замените пути) — [scripts/cron.example](scripts/cron.example). Для лучшей полноты рекомендуется ежечасный запуск. Каждый успешный запуск обновляет суточные снимки для всех трёх периодов; повторный запуск не удваивает наблюдения. Блокировка PostgreSQL предотвращает одновременные сборы. Снимки пишутся транзакционно. Не запускайте расписание в браузере или внутри Next.js процесса.

Альтернатива — планировщик, отправляющий **POST** `/api/cron` с заголовком `Authorization: Bearer <CRON_SECRET>`. Токен не передаётся в URL. При больших объёмах используйте CLI-worker: лимит времени serverless может прервать обработку. После аварийного завершения запись running в журнале может остаться; проверьте процесс перед повторным запуском.

## API

- `GET /api/radar?period=1&limit=100&q=...&hits=0` — рейтинг, сводка, история и источники.
- `GET /api/export` — те же фильтры, CSV UTF-8 с BOM, защита от формул электронных таблиц.
- `POST /api/admin/login` — JSON `{password}`, вход.
- `POST /api/admin/logout` — выход.
- `GET /api/admin/status` — настройки без секретов, журнал (сессия).
- `POST /api/admin/vk/probe` — защищённая проверка владельца токена и доступных методов, без возврата секретов (сессия + Origin).
- `POST /api/admin/collect` — сбор (сессия + Origin).
- `POST /api/cron` — сбор (Bearer CRON_SECRET).

## Проверки и production

```sh
npm run typecheck
npm test
npm run build
npm start
```

Тесты проверяют извлечение и дедупликацию audio, отсутствие вымышленных вложений, фильтры, CSV и сессии. Интеграционный тест SQL: `TEST_DATABASE_URL=... node --import tsx --test tests/database.integration.ts` (использует отдельную схему, удаляемую после теста). Для production сначала выполните миграцию. БД не открывайте в интернет; Compose привязывает её только к loopback и сохраняет данные в volume. Настройте резервное копирование, мониторинг журнала и внешний HTTPS reverse proxy; при проксировании задайте APP_ORIGIN (например https://radar.example.com) и сохраняйте правильные Host/Origin. Не публикуйте локальные dev-секреты.

## Структура

`app/` — страницы и HTTP API; `components/` — адаптивная панель; `lib/` — PostgreSQL, VK, сбор, аналитика и авторизация; `scripts/schema.sql` — идемпотентная схема; `scripts/` — миграция, проверка VK, worker и cron; `tests/` — проверки; `docs/` — методология и ограничения.
