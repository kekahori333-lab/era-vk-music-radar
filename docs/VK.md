# Проверка официального VK API

На этапе реализации 01.11.2026 просмотрены определения методов из официального репозитория VKCOM/vk-api-schema:
- https://github.com/VKCOM/vk-api-schema/blob/master/newsfeed/methods.json — `newsfeed.search`, поиск публикаций, типы токена в схеме: user, service. Параметры включают q, start_time, end_time, start_from.
- https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json — `wall.get`, чтение стены, user/service. Поддерживает страницы offset/count и фильтр.
- https://dev.vk.com/ru/method/newsfeed.search
- https://dev.vk.com/ru/method/wall.get

Важно: схема описывает контракт, но **не доказывает фактическую доступность** метода конкретному приложению и не гарантирует выдачу audio. Доступ dev.vk.com из текущей среды был заблокирован прокси (403). Проверка с реальным токеном не выполнена: токен и стены не предоставлены. Подтверждённых прав или глобального музыкального поиска нет. Не следует обещать, что scope `audio` или `wall` автоматически решит ограничения приложения. Не используйте чужие токены, неофициальные клиенты, парсинг закрытых страниц или обход ограничений.

## Обязательная проверка перед включением сбора

1. Зарегистрируйте приложение официальным способом; ознакомьтесь с актуальными условиями и разрешениями VK. Настройте выданный приложению токен в `VK_ACCESS_TOKEN` и явный список доступных публичных стен в `VK_WALL_IDS`.
2. Запустите `npm run vk:probe`. Команда обращается только к официальным методам, сообщает код отказа и число фактически полученных audio-вложений. Нулевое число audio не доказывает невозможность их получения: тестируется только один пост.
3. При ошибках доступа остановитесь и проверьте тип токена, разрешения и доступ приложения через официальный кабинет. Код ошибки сохраняется, токен не выводится. Не активируйте недоступные методы обходными путями.
4. Запустите `npm run collect`. Метод newsfeed.search не участвует в рейтинге: его поисковая выдача не является переписью всего VK. Коллектор использует wall.get только для настроенных стен, максимум 10000 постов каждой стены за запуск. Достижение лимита помечается в журнале.

## Что измеряется

Одна пара post_id / audio_id учитывается один раз. Идентификатор audio — owner_id + id: разные загрузки песни **не объединяются** автоматически. Пост с copy_history считается репостом; учитываются доступные аудио из непосредственного поста и доступной истории репоста. Авторы определяются from_id, при отсутствии — owner_id. Автор репоста и автор оригинального произведения — разные понятия.

Сбор добавляет/обновляет наблюдения. Это не синхронное зеркало: удалённый после сбора пост может остаться в истории. Первичная история — до 30 дней; для честного сравнения двух 30-дневных интервалов требуется до 60 дней накопления. Пропуски между запусками, закрытые стены, неполные вложения и ошибки API ограничивают результат. Позиция сравнивается с вчерашним снимком UTC, а не с соседним скользящим интервалом.

ТОП-N выбирается из общего рейтинга наблюдаемой выборки, затем применяются поиск и фильтр новых хитов. Числа в верхних карточках описывают уникальные музыкальные посты всей выборки выбранного периода, не сумму по трекам (один пост может содержать несколько треков). Ссылки ведут на последние пять наблюдавшихся публикаций трека.

## Подключение личной страницы

Ссылка на страницу не является авторизацией. В текущей реализации нет автоматического входа VK ID: для такого входа сначала нужны зарегистрированное приложение, подтверждённый подходящий способ авторизации и рабочий callback на домене сервиса. Не вводите вымышленные домены или адрес GitHub в форму VK ID. Наличие приложения VK ID не доказывает разрешение читать посты и музыку.

Кнопка «Проверить подключение VK» в защищённой админке использует только серверный VK_ACCESS_TOKEN. Через users.get без user_ids она пытается определить владельца пользовательского токена. Официальная схема: https://github.com/VKCOM/vk-api-schema/blob/master/users/methods.json. Для сервисных токенов личная страница может не определяться; доступность wall.get проверяется независимо. Ошибки доступа возвращаются контролируемым сообщением и кодом, без сырых ответов VK и секретов.
