# Проверки реализации

Проверено в облачной среде на Node.js 24 и PostgreSQL 17.

- `npm ci` — воспроизводимая установка по lockfile успешна. Повторная миграция также прошла.
- `npm start` — production-сервер запущен и проверен: HTML, рейтинг из PostgreSQL, CSV и запрет неавторизованного доступа к admin/cron.
- `npm run typecheck` — успешно.
- `npm test` — 7 тестов, 7 успешно: извлечение и дедупликация вложений, отсутствие вымышленных данных, фильтры, CSV, подпись сессии, список стен, CSRF/Origin.
- `TEST_DATABASE_URL=... npm run test:integration` — 1 интеграционный тест, успешно: два повторных сбора, дедупликация, оригиналы/репосты/авторы, снимки, рейтинг, периоды, поиск, новые хиты, источники и фиксация отказа VK. Сетевые ответы VK подменены только внутри теста; PostgreSQL настоящий. Схема теста удалена после завершения.
- `npm run build` — production-сборка Webpack успешна. Turbopack не используется: sandbox среды запрещает необходимое ему связывание внутренних сокетов.
- Chromium, размеры 1440×1000 и 390×844 — проверены загрузка, пустые состояния, поиск, ТОП/периоды, новые хиты, вход с неверным и правильным паролем, выход, экспорт CSV, 401 на закрытых API, мобильное меню и отсутствие горизонтального переполнения страницы. Ошибок выполнения JavaScript не обнаружено.
- Отдельный браузерный сценарий с перехватом ответа API проверил карточку трека, график, ссылку на публикацию, закрытие Escape и сообщение об ошибке базы. Эти данные не вставлялись в БД приложения.

Реальные запросы VK с пользовательским токеном **не проверены**: токен и список стен отсутствуют. `npm run vk:probe` корректно сообщает об отсутствии настройки. Возможности официальной схемы и ограничения источника описаны в [VK.md](VK.md). Нет утверждения о полном охвате VK.

Рабочая БД после проверки не содержит тестовых публикаций. Автоматическое расписание и публичное развёртывание не включались: подготовлены worker, пример cron и защищённый endpoint для внешнего планировщика.

## Подготовка Neon

Установлен Neon CLI 8.16.0. `neon init -y --org-id org-lingering-hat-13461519 --project-id snowy-bonus-73162624 --branch production --services postgres` создал привязку без сетевой проверки и `neon.ts`. `neon deploy` и `neon login` завершились сетевой ошибкой; HTTPS к API получил 403 от прокси. Подключение именно к Neon и получение его переменных не подтверждены.

После добавления управления пулом Vercel, прямого соединения сборщика и согласованной загрузки .env-файлов: `npm run typecheck` успешно; `npm test` — 9/9; локальный SQL-интеграционный тест — 1/1; миграция локальной БД успешна; `npm run build` успешно. Новая production-сборка запущена и проверена запросами: `/` 200, `/api/radar` 200 с available=true, `/api/export` 200 CSV, `/api/admin/status` 401. Это локальные проверки PostgreSQL, а не успешный Neon deploy. Инструкции продолжения: [NEON.md](NEON.md).

## Режим CSV без ответа VK

- `npm test`: 14 тестов, 14 успешно.
- `TEST_DATABASE_URL=... npm run test:integration`: 2 теста, 2 успешно. Файлы выполняются последовательно, поскольку advisory-блокировка сбора общая на всю БД даже при разных тестовых схемах. Проверены API-сбор, CSV, повторная загрузка, атомарный откат конфликтующего файла, смешанная выборка и ежедневные снимки без токена.
- `npm run build`: production-сборка успешна; добавлены защищённые `/api/admin/import` и `/api/admin/import/template`.
- Chromium с production-сборкой и изолированной PostgreSQL-схемой: вход, пустой шаблон, предпросмотр без записи, подтверждение импорта, реальные SQL-метрики, карточка/график/источники, новые хиты, CSV-экспорт с пометкой источника, повторная загрузка, запрет чужого Origin/неподтверждённого импорта, лимит запроса, Bearer-защита cron и снимки без VK, мобильная ширина 390px. Ошибок JavaScript нет. Тестовая схема удалена, основная БД не заполнялась фикстурами.
- Новых таблиц CSV-режим не требует. `vercel.json` описывает ежедневный вызов в 00:10 UTC; выполнение расписания на Vercel надо проверять после публикации, локальный вызов подтверждает только код endpoint.
