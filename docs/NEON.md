# Подключение Neon

Проект: `snowy-bonus-73162624`, организация: `org-lingering-hat-13461519`, ветка: `production`.

`neon init` создал локальную привязку `.neon` и типизированный `neon.ts`. `.neon` и файлы `.env*` (кроме шаблона) исключены из Git. PostgreSQL — единственный требуемый сервис. Neon Auth, Functions, Storage и Data API не включаются: сайт уже использует серверные обработчики Next.js и собственную административную сессию.

## Первое подключение

```sh
npm i -g neon@latest
# Если глобальная установка не работает, замените neon на npx neon@latest.
neon login
neon init -y --org-id org-lingering-hat-13461519 --project-id snowy-bonus-73162624 --branch production --services postgres
neon deploy
```

Завершите вход в браузере, когда CLI его запросит. Автономное сообщение `Written offline (--no-checks)` подтверждает только запись файлов: оно не доказывает доступ к проекту. `neon deploy` должен успешно применить конфигурацию и записать переменные. Существующий `.env` сохраняет пользовательские настройки, а CLI обновляет управляемые Neon поля. Если `.env` отсутствует, CLI может использовать `.env.local`. Не выводите содержимое этих файлов в чат или логи.

Сетевой доступ к `console.neon.tech` необходим для CLI; к домену endpoint конкретной БД — для PostgreSQL. В управляемой среде TCP-доступ может требовать отдельного разрешения. HTTP-allowlist не даёт доступа PostgreSQL по TCP. Не отключайте проверку TLS и не обходите сетевой прокси.

## Соединения и схема

- `DATABASE_URL`: pooled URL для запросов сайта.
- `DATABASE_URL_UNPOOLED`: прямой URL для миграций и сборщика. Сборщик использует session advisory lock, который нельзя держать через transaction pooling.
- Для локального PostgreSQL без PgBouncer разрешено использовать один `DATABASE_URL`.

Драйвер `pg` сохранён. В Vercel (`VERCEL=1`) пулы регистрируются через `attachDatabasePool` из `@vercel/functions`; idle-соединения освобождаются через 5 секунд. Next.js и CLI-скрипты одинаково загружают `.env.local` и `.env` через `@next/env`. URL БД доступны только серверу. TLS-настройки Neon URL сохраняются.

После получения настоящих переменных протестируйте схему на изолированной ветке/тестовой БД. Укажите её прямой URL в защищённом `TEST_DATABASE_URL` и выполните:

```sh
npm run test:integration
```

Тест создаёт отдельную схему и удаляет её после проверки, но не выбирает/создаёт ветку Neon самостоятельно. Сохраните резервную точку перед применением миграции к production.

```sh
npm run db:migrate
npm run build
npm start
```

Проверьте HTTP 200 и `available: true` на `/api/radar`, CSV на `/api/export` и вход/выход `/admin`. Пустой рейтинг допустим до получения настоящих данных VK; HTTP 503 не подтверждает работающее соединение.

## Vercel

Локальный `neon deploy` не обновляет переменные Vercel. Подключите Neon к проекту Vercel либо добавьте `DATABASE_URL` и `DATABASE_URL_UNPOOLED` в Settings → Environment Variables безопасным способом. Сохраните отдельные `ADMIN_PASSWORD`, `SESSION_SECRET`, `CRON_SECRET` и `APP_ORIGIN`. Выполните Redeploy. Секреты не включаются в репозиторий.

## Текущее ограничение

В этой сессии `neon deploy` и `neon login` завершились сообщением `Could not reach the Neon API`. Контрольный HTTPS-запрос к `console.neon.tech` получил HTTP 403 от прокси. Требуемые домены добавлены в черновик конфигурации среды; сохранение черновика не применяет правила к работающей машине. Успешный удалённый deploy, получение переменных, миграция и end-to-end проверка именно Neon пока не подтверждены. Локальная PostgreSQL-проверка не заменяет проверку Neon.

Пользователь позднее подключил эту базу к Vercel через официальную интеграцию, создал шесть таблиц через SQL Editor и получил available=true на публичном /api/radar. Это подтверждает соединение Vercel с БД; доступ CLI из облачной среды остаётся отдельным неподтверждённым каналом.
